# Timer0 串口接收超时中断 — 修复计划

## 当前问题

输出乱码，原因有两个：

### Bug 1：定时器计算公式错误

```c
// 当前代码（错误）
u32 timeout_us = (35UL * 1000000UL) / baudrate;  // 35 * 1000000 / 115200 = 30381us = 30ms!
timer0_reload_val = 65536UL - (u16)((MAIN_Fosc / 1000000UL) * timeout_us);
```

`35` 应该是 `3.5`（3.5个字符时间），但整数运算中写成 `35` 就变成了35个字符时间，导致 timeout 计算偏差。

### Bug 2：使用了自动重装模式（TMOD mode 0 = 16位自动重装）

自动重装模式下，定时器溢出后自动从 TH0/TL0 重装并继续计数。ISR 中 `TR0 = 0` 停止定时器，但溢出到 ISR 执行之间有延迟，定时器可能已经重新触发。应该用 **mode 1（16位非自动重装）**，溢出后定时器自然停止，由 UART ISR 手动重装启动。

## 修复方案

### 修改1：`src/STC8G_H_Timer.c` — 修正 `UART_Timeout_Timer0_Config`

```c
void UART_Timeout_Timer0_Config(u32 baudrate)
{
    // 3.5字符时间的timer ticks = 3.5 × 11bits × MAIN_Fosc / baudrate
    // = 38.5 × MAIN_Fosc / baudrate
    // 为避免浮点，用 385 × MAIN_Fosc / (baudrate × 10)
    u32 timer_ticks = (385UL * MAIN_Fosc) / (baudrate * 10UL);
    timer0_reload_val = 65536UL - (u16)timer_ticks;
    
    Timer0_Stop();
    TMOD = (TMOD & ~0x03) | 0x01;  // ★ Mode 1: 16位非自动重装
    Timer0_CLK_Select(1);           // 1T模式
    Timer0_CLK_Output(DISABLE);
    T0_Load(timer0_reload_val);
    ET0 = 1;                        // 使能Timer0中断
    TR0 = 0;                        // 先不启动
}
```

以 115200 baud 验证：`385 × 11059200 / (115200 × 10) = 385 × 11059200 / 1152000 = 3686 ticks`
`65536 - 3686 = 61850`，超时时间 = 3686 / 11.0592MHz = 333us（正确）。

### 修改2：`src/STC8G_H_Timer_Isr.c` — 无需改动

ISR 已经正确：`TR0 = 0; uart_rx_timeout_flag = 1;`

### 修改3：`src/STC8G_H_UART_Isr.c` — 无需改动

已在收到字节后重装并启动 Timer0。

### 修改4：`src/main.c` — 无需改动

主循环已正确检测标志并回显。
